# 拾音 v2 设计：桌面增强、音源适配器、问题清单

本文是 v0.1 之后的规划，按“做 / 不做 / 以后再说”给出结论。v0.1 的设计见 `DESIGN.md`。

## 1. 结论速览

| 项目 | 结论 | 理由 |
| --- | --- | --- |
| 桌面歌词（浮动歌词） | 做，v0.2 | 同类桌面播放器的标配，实现成本可控 |
| 迷你播放器（小窗口） | 做，v0.2 | 和桌面歌词共用一套子窗口机制，边际成本低 |
| 系统托盘 + 全局快捷键 | 做，v0.2 | 关窗后仍能控制播放，是小窗和桌面歌词的前提 |
| 任务栏缩略图按钮 | 做，v0.3 | 体验好，但需要调用 Win32 接口，单独排期 |
| 悬浮球 | 不做 | 和迷你播放器功能重叠；常驻置顶的小圆点在 Windows 上打扰大于价值 |
| 逐字歌词（YRC） | 做，v0.3 | 需要换用 eapi 歌词接口，播放页和桌面歌词都能受益 |
| 音源适配器架构 | 做，分两步 | 先在 Rust 内部抽象成 trait（v0.2），暂不开放第三方脚本插件 |
| 第三方 JS 插件（MusicFree 式） | 暂不做 | 安全风险和维护成本高，和“轻量”定位冲突 |
| 本地音乐库 | 以后再说 | 有了适配器以后，可以作为第二个适配器加入 |

参考过的开源项目：

- MusicFree：播放器只负责播放，搜索、播放地址、歌词都由插件提供。
- SPlayer：Windows 上的桌面歌词和任务栏歌词。
- nnplayer、TuneFree：Tauri 2 下的桌面歌词窗口实现，包括透明背景、置顶、锁定、拖拽、位置持久化、防止外接屏拔出后窗口跑到屏幕外。

## 2. Windows 桌面增强

### 2.1 总体做法

主窗口之外，再开两个独立的 Tauri 子窗口：`lyrics`（桌面歌词）和 `mini`（迷你播放器）。

- **播放只在主窗口**：`<audio>` 只存在于主窗口。子窗口只负责显示和发送控制指令，不各自播放。
- **关掉主窗口不停播**：关闭主窗口时只隐藏到托盘，不退出，音乐继续放。
- **状态同步**：主窗口通过 Tauri 事件广播播放状态，事件名 `player:state`，内容包括曲目、播放状态、当前歌词行、主题色。
  - 播放进度不逐帧推送，只推送“开始时间 + 播放速率”。子窗口自己用 rAF 推算当前进度，跨窗口通信每秒不到 2 次。
  - 子窗口发出的控制指令走 `player:control` 事件，由主窗口执行。
- **构建方式**：子窗口用 Vite 多入口构建（`lyrics.html`、`mini.html`），只引入需要的组件，每个入口 JS gzip 后控制在 15 KB 以内。

### 2.2 桌面歌词

| 方面 | 设计 |
| --- | --- |
| 外观 | 透明无边框，置顶，不在任务栏显示。两行：当前行加下一行（或译文）。字体 28px 粗体，白字加柔和描边和投影，保证在任意背景上都看得清 |
| 交互 | 鼠标悬停时淡入一条工具栏：上一首、播放/暂停、下一首、字号 ±、锁定、关闭 |
| 锁定 | 锁定后鼠标穿透（`set_ignore_cursor_events`）；托盘菜单或全局快捷键可以解锁 |
| 拖拽 | 未锁定时可拖动；位置和尺寸自己保存，启动时检查是否还在屏幕范围内 |
| 动画 | 换行时当前行向上淡出 6px，新行淡入；有逐字歌词时用 `background-clip: text` 做渐变扫光，只动 transform 和背景位置 |
| 设置 | 字号、颜色（默认跟随封面主题色，可固定）、是否显示译文、单行或双行 |
| 不做 | 卡拉 OK 式双色描边、背景模糊（WebView2 透明窗口里开模糊既费资源又容易出问题） |

### 2.3 迷你播放器

- **尺寸**：340×88，圆角 14，不透明背景，带细描边，不用毛玻璃。
- **内容**：左侧 64px 封面；中间两行，歌名和歌手，或者当前歌词；右侧上一首、播放、下一首。底部 2px 进度条。
- **入口**：主窗口标题栏按钮或快捷键 `Ctrl+Shift+M`。迷你窗口和主窗口二选一显示，双击封面回到主窗口。
- **置顶**：默认置顶，可以取消。

### 2.4 托盘与快捷键

- **托盘菜单**：显示主窗口、播放/暂停、上一首、下一首、桌面歌词（勾选）、锁定歌词、迷你模式、退出。
- **全局快捷键**：用 `tauri-plugin-global-shortcut`，默认不注册，在设置里逐项开启，避免和其他软件冲突。
  - `Ctrl+Alt+P`：播放/暂停
  - `Ctrl+Alt+←/→`：上一首 / 下一首
  - `Ctrl+Alt+L`：桌面歌词
- **系统媒体键**：已经通过 MediaSession 支持，WebView2 会对接系统媒体控制，不需要另外实现。

### 2.5 资源预算

| 项目 | 目标 |
| --- | --- |
| 每个子窗口 | 一个独立的 WebView2 渲染进程，约 25–40 MB。默认不创建，打开时才创建，关闭时销毁，不只是隐藏 |
| 空闲 CPU | 桌面歌词在没有播放时停止 rAF，CPU 接近 0 |
| 新增 Rust 依赖 | 只加 `tray-icon`（Tauri 自带 feature）和 `global-shortcut` 插件 |

## 3. 架构：播放器 + 音源适配器

### 3.1 现状

当前已经拆成 `core`、`server`、`src-tauri`、`web` 四块。耦合主要在三处：

1. **`core::api::Netease` 被直接引用**：`download`、`jobs`、`link` 都写死依赖它，换音源要改所有调用方。
2. **数据模型带有网易云特征**：`Track.id` 是 `u64`，`fee` 是网易云的会员标记，`cover` 依赖 `?param=` 裁剪参数。
3. **前端写死网易云**：`transport.ts` 的接口名、链接识别、榜单 ID 都是网易云专用的。

播放、队列、歌词、下载、标签写入、任务调度这些部分本身和音源无关，已经可以复用。

### 3.2 目标结构

```
crates/
  core/          通用：模型、歌词、标签写入、下载任务、凭证存储
  source/        Source trait 和注册表
  source-netease/ 网易云适配器（现在的 api.rs、crypto.rs、link 识别）
  server/        Web 版
src-tauri/       桌面版
web/             前端，按“能力”显示功能，不写死音源
```

### 3.3 Source trait

```rust
#[async_trait]
pub trait Source: Send + Sync {
    /// 唯一标识，例如 "netease"
    fn id(&self) -> &'static str;
    fn info(&self) -> SourceInfo;          // 名称、图标、支持的能力、音质列表

    /// 识别用户粘贴的链接，不认识的返回 None
    fn parse_link(&self, text: &str) -> Option<Target>;

    async fn search(&self, q: &str, page: Page) -> Result<Vec<Track>>;
    async fn track(&self, id: &str) -> Result<Track>;
    async fn collection(&self, kind: CollectionKind, id: &str) -> Result<Collection>;
    async fn stream(&self, id: &str, quality: &str) -> Result<Stream>;   // 地址、格式、过期时间、是否试听
    async fn lyric(&self, id: &str) -> Result<Lyric>;                    // lrc、译文、逐字歌词（可选）

    /// 可选能力，默认返回 Unsupported
    async fn login_qr(&self) -> Result<QrStart> { Err(Error::Unsupported) }
    async fn account(&self) -> Result<Option<Account>> { Ok(None) }
}
```

数据模型的调整：

- **`Track`**：增加 `source: &'static str`，`id` 改为 `String`。会员标记 `fee` 改成通用的 `availability: Free | Vip | Paid | Unavailable`。
- **封面**：`cover` 保留原始 URL，缩放交给适配器提供的 `cover_url(url, size)`。网易云用 `?param=`，其他音源原样返回。
- **下载与任务**：`download` 和 `jobs` 只依赖 `&dyn Source`，按 `track.source` 从注册表里取对应的适配器。

前端的调整：

- **统一接口**：`transport.ts` 只暴露 `sources()`、`search(source, q)`、`stream(track)` 这类通用接口。
- **按能力显示**：界面根据 `SourceInfo.capabilities` 决定显示哪些功能，例如没有登录能力的音源就不显示登录入口。
- **链接识别**：粘贴链接时依次交给各个适配器的 `parse_link` 识别。

### 3.4 为什么不做 JS 插件

MusicFree 的插件是任意 JS 代码，和应用跑在同一个上下文里，它的文档也明确说了有安全风险。拾音的 Web 版部署在公网，执行第三方脚本风险太高。

所以先用 Rust trait 把边界划清楚。以后如果确实需要第三方扩展，再考虑在 Rust 侧用 QuickJS（rquickjs）沙箱加载，只开放 `fetch` 和 `crypto`，不开放文件系统。

### 3.5 迁移步骤

每一步都能独立发布：

1. 把 `crypto.rs`、`api.rs`、`link.rs` 移到 `source-netease`，`core` 改为依赖 trait。对外接口不变。
2. `Track.id` 改为字符串，并加上 `source` 字段。前端类型同步修改，历史记录做一次兼容迁移。
3. 前端去掉写死的网易云逻辑（榜单 ID、链接正则、`img()` 的裁剪参数），全部改为从 `SourceInfo` 读取。
4. 加入第二个适配器验证抽象是否合适。建议先做“本地文件夹”：只用到 `search`、`stream`、`lyric`，没有网络和登录，最容易暴露 trait 设计上的问题。

## 4. 解析与播放问题清单

以下问题都是实际检查过的。

### 4.1 已修复（本次提交）

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 服务器在海外，版权按地区判断 | 预览服务器在德国，所有歌曲 `privilege.st = -100`，播放地址返回 404，连免费歌曲都放不了 | 新增 `SHIYIN_REAL_IP`，请求带上 `X-Real-IP`（社区通用做法），预览服务器已配置。桌面版在国内直接请求，不需要这一项 |
| 试听片段被当成完整歌曲 | 未登录或非会员时，部分歌曲只返回 30 秒片段，下载下来的文件不完整 | 解析 `freeTrialInfo`：下载时直接报错并说明原因；播放时显示“试听”标记并提示 |

### 4.2 待修复

| 优先级 | 问题 | 现象 | 方案 |
| --- | --- | --- | --- |
| 高 | 列表不显示是否可播放 | 版权受限的歌曲点了才报错 | 搜索和歌单接口都会返回 `privilege`。据此给每首歌标记可用性：不可播放的置灰，自动播放时跳过 |
| 高 | 播放地址过期 | 暂停超过 20 分钟后继续播放，或拖动进度时，CDN 返回 403 | 现在出错时会重试一次。改为记录地址的获取时间，接近过期时主动刷新，并保持当前进度 |
| 中 | 只有逐行歌词 | 没有逐字歌词（YRC） | 改用 eapi 的 `/song/lyric/v1` 并带上 `yv=1`，解析 `[开始,时长](字开始,字时长,0)字` 格式 |
| 中 | 音质降级没有提示 | 选“无损”但账号没有权限时，实际拿到的是 320k | 比较请求的音质和返回的 `level`，不一致时在界面上标出实际音质 |
| 中 | 大歌单只显示前 1000 首 | 超过 1000 首的歌单被截断 | `n=0` 时 `trackIds` 是完整的，但要确认 `/v6/playlist/detail` 在超大歌单下的行为，必要时改用 `/playlist/track/all` 分页 |
| 中 | 接口没有缓存 | 来回切换页面时重复请求同一个歌单 | 前端加一层内存 LRU 缓存（歌单和专辑 5 分钟，歌词长期缓存）；Rust 侧缓存歌曲详情 |
| 低 | 请求频率过高会被风控 | 网易云返回 `-460 Cheating` | 识别这个错误码，给出明确提示；批量下载时降低并发并加随机间隔 |
| 低 | 杜比全景声等音质 | `dolby`、`vivid` 两档音质目前不支持 | 加入音质列表，需要注意设备和账号是否支持 |
| 低 | FLAC 写标签要读整个文件 | 大的母带文件写标签慢，内存占用高 | `metaflac` 会读入整个文件，可以改为只重写头部的元数据块，再接上原来的音频数据 |

### 4.3 其他代码层面的问题

- **Web 版播放走浏览器直连**：音频直接从网易云 CDN 加载。用户在国外时同样会遇到地区限制，而服务端的 `X-Real-IP` 管不到浏览器。可选方案：服务端提供 `/api/stream` 代理（只允许白名单域名，支持 Range 请求）。代价是占用服务器带宽，默认关闭。
- **口令强度**：Web 版目前只有一个口令，没有限制尝试次数。建议在 Nginx 上加 `limit_req`，并在服务端对连续失败的 IP 延迟响应。
- **凭证明文存储**：桌面版的凭证可以改存到 Windows 凭据管理器（`keyring` crate），服务端维持 0600 权限的文件即可。
